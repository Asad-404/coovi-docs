# Needed before going live

What has to change before Coovi takes real orders from real customers. Written 2026-10-13 from a read of the code in all three repos and of `QUICK_STATUS.md`; update it as items are done. Done items re-checked against GitHub on 2026-10-15.

## How to read this file

- **Priority 1**: fix before taking real orders. Each one can lose an order, lose data, or leak a customer's details.
- **Priority 2**: fix in the first weeks after launch, before orders become frequent.
- **Priority 3**: worth doing as the shop grows.
- **Who**: **You** means it needs your own accounts, money, credentials or business decisions; Claude cannot do it. **Claude** means Claude can build it in a pull request for you to review and merge. **Both** means you decide or sign up first, then Claude builds.

What is already in good shape (no action needed): prices, totals and the delivery fee are computed by the API, never trusted from the browser; order status only moves forward and stock changes are safe when two admins click at once; the API refuses to start in production with a weak secret, weak admin password or localhost CORS; login, checkout and order lookup are rate limited; all three repos have CI with tests.

Items 26 and 29 to 37 come from the security review of 2026-10-13 (all three apps on `master`). The full report, with file and line evidence, is in the project files as `security/SECURITY_REVIEW_2026-10-13.md`.

Upgrade to `next` 16.3.8 or later. | Publicly known holes on the shop's front door. Our share images use fixed text, so the critical one is probably hard to exploit here (inferred, not tested), but the fix is a version bump. | Claude |

## Priority 2: first weeks after launch

| # | Item | Why it matters | Who |

| 13 | **Error tracking.** The API only prints errors to Render's log, which you never see unless you look. Add a free error tracker (for example Sentry) to the API, storefront and admin. | A broken checkout is silent today: you only find out when a customer complains, or never. | Both: you create the free account; Claude wires it in |
| 14 | **Uptime alert.** A free monitor (for example UptimeRobot or Better Stack) that checks `https://<api>/health` every few minutes and messages you when it fails. | You learn the shop is down before customers do. | You (5 minutes to set up; Claude can write the steps) |
| 15 | **Done: coovi-api#36, coovi-admin#29, coovi-storefront#27 (merged 2026-10-27): a "Confirmed by call" tick in the admin with a warning before Processing, at most 3 unconfirmed orders per phone, and 5 checkouts an hour per address (was 20).** **Fake cash-on-delivery orders.** Checkout can't prove the phone belongs to the person ordering. | Fake orders waste courier fees and block stock. Call every website order before Processing. Add an SMS code at checkout (only for new or risky numbers) once an SMS company is chosen, if fakes still appear. Check item 33 before launch: if every visitor shares one address, 5 an hour would be the limit for the whole shop. | Both: you decide; Claude builds verification if needed |
| 16 | **Stock is only taken when you confirm an order.** Two customers can both order the last piece; the second confirmation then fails with "insufficient stock". | Sarees are often one of a kind, so this will happen. Decide: reserve stock when the order is placed (the customer sees "sold out" at once) or keep today's rule and call the second customer. | Both: you decide; Claude builds |
| 17 | **Done: merged 2026-10-13 and the real fees are set on Render.** **Delivery fee by area.** Built, in review 2026-10-13 (coovi-api#14, coovi-admin#16, coovi-storefront#15). Still needed: your real fees for inside Dhaka city and outside Dhaka, set as `DELIVERY_FEE_INSIDE_DHAKA` and `DELIVERY_FEE_OUTSIDE_DHAKA` on Render (placeholders 70 and 130). | Outside-Dhaka delivery usually costs more; a flat fee either loses money or overcharges Dhaka customers. | You (tell Claude or set the values) |
| 18 | **In review 2026-10-15: sign out everywhere on password change, per-person accounts with roles and per-person View and Edit access (branch `claude/project-thread-deqibw`). Two-step login is still open.** **Admin sign-in strength.** One shared admin account, no two-step login, a sign-in stays valid for 1 day even after the password is changed, and the token sits in browser storage. | Whoever gets the admin password or a logged-in laptop can see every customer's address. Add sign-out-everywhere on password change first; two-step login and per-person accounts (plan feature 13) later. | Claude |
| 19 | **Customer data handling.** The orders CSV export puts every name, phone and address on your laptop; Atlas network access is probably open to every address (Render's free plan has no fixed IP). | A lost laptop or a leaked database password exposes customers. Keep exports in an encrypted folder and delete old ones, use a long Atlas password for the production user, and decide how long to keep old orders. | You |
| 20 | **Fixed in coovi-api PR #12 (merged 2026-10-13).** **Order numbers use UTC dates.** Orders placed between midnight and 6 am Bangladesh time get the previous day's date. | Confusing when matching orders to days. Small fix with item 7. | Claude |
| 21 | **Done: coovi-admin#17 (merged 2026-10-14).** **Hide the admin from search engines.** The admin site has no `noindex`. | The login page can show up in Google. | Claude |
| 26 | **Done: coovi-admin#17 and coovi-storefront#21 (merged 2026-10-14).** **Security headers on the admin and storefront.** Moved up from Priority 3 by the 2026-10-13 security review. The admin sends no `X-Frame-Options` or Content Security Policy, so another site can show it in a hidden frame and trick you into clicking (clickjacking); a CSP is also the safety net that keeps the admin token in browser storage (item 18) from being stolen if a script-injection bug is ever added. | Small config change in `vercel.json` (admin) and `next.config.ts` (storefront); do it with item 21. | Claude |
| 30 | **Automatic dependency security alerts.** The weekly Dependabot version-update config was added on 2026-10-14 and removed the same day by owner choice, because its "Bump" pull requests were noise. Security fixes stay covered by GitHub's own setting: turn on **Dependabot alerts** and **Dependabot security updates** in each repo (Settings → Code security). CI still does not run `pnpm audit`. | A published hole in a dependency would otherwise sit unnoticed; with security updates on, GitHub opens a pull request only when a real hole is found. | You: switch on both settings in coovi-api, coovi-admin and coovi-storefront |
| 31 | **Done: coovi-api#23 (merged 2026-10-14).** **Fake orders can use up the email alert quota.** Every website order sends one email, and checkout allows 20 orders an hour per IP; Resend's free plan sends about 100 emails a day. | A burst of junk orders stops alerts for real orders until the next day, without you noticing. Send one summary email per few minutes during bursts and log when the quota is used up. Related to item 15. | Claude |
| 32 | **Done: coovi-api#23 (merged 2026-10-14).** **Public order lookup returns internal fields.** `GET /api/orders/:orderNumber` returns the whole order, including `createdBy` (the admin's email on manual orders). | The admin email is half of the admin login, and future internal fields (staff notes, history) would leak the same way. | 33 | **Check the rate limits see real visitors on Render.** The API trusts exactly one proxy (`TRUST_PROXY`, default 1). If Render has more, every visitor looks like the same address. | Then one person's 5 wrong passwords would lock you out of the admin for 15 minutes, and 20 orders an hour would be the limit for the whole shop. Check `req.ip` from two networks and set `TRUST_PROXY` to match. | Both: Claude writes the check; you run it on the live API |
| 39 | **The privacy policy does not mention the order phone cookie.** Its cookies section only names the Meta Pixel, but checkout and Track Order keep the customer's phone in a browser cookie for a week. | The policy should say what is stored about the customer. | Claude |
